# DECISIONS, Cotejo (Week 10, Business Bending)

## Session 1 (2026-10-18): packet, then build
- **Slice:** the Team 8 Blueprint, Technologist lens. Vacuum: Regret Prevention. A first-year Mexican university student looking at a laptop listing compares what she declares about the laptop with the published requirements of the software her degree needs. Not a store, not a recommendation engine.
- **Name:** Cotejo ("to compare against a source"). Emilio asked for alternatives (including something like "funds" in Spanish), then decided to keep Cotejo.
- **Packet before code:** `docs/PACKET.md` is the first commit (0ce30f5). Every code commit comes after it.
- **Declaration honored:** a deterministic, source-backed checker (Blueprint Condition 1). The app works with no AI at all.
- **Three states, never a grade:** every requirement is `meets`, `does_not_meet` or `cannot_decide`; `below_recommended` is shown separately as information. Unknown input is never a failure. There is no overall score, no ranking and no "good laptop" label, and "no evidence loaded" is worded differently from "does not meet".
- **Evidence catalog:** 5 titles (AutoCAD 2026, MATLAB R2026b, SOLIDWORKS 2026-2027, Adobe Premiere 26.x, Visual Studio 2022). Every requirement carries the vendor's own words, the URL and the retrieval date (2026-10-18). `lib/validate.ts` rejects a requirement that lacks any of them. The catalog is versioned (v2026-10-18.1) and every saved check stores the version it was computed with.
- **Dragon Stack:** (1) LLM, Gemini free tier, optional text helper; (2) user-constraint data, the declared specs and budget checked against the catalog; (3) vision, an optional listing screenshot. The model only proposes form fields. The student confirms each one (confirm box required) and the engine decides.
- **Condition 4 resolution:** AI is boxed in. Proposed fields are marked "Propuesto por IA: confirma"; the server refuses the check until the student confirms; each saved check logs whether AI was used and how many proposed fields she changed (`ai_fields_proposed`, `ai_fields_changed`). Screenshots and free text are never stored. Daily AI limit of 30 per user, counted from consent rows.
- **Shadow clause by design:** no purchase links, no store names, no commissions. `lib/wording.ts` scans for pressure language and purchase links; `scripts/verify.ts` scans the source tree and the schema (514 checks). Which? was rejected as a model because it takes affiliate commissions, which conflicts with Condition 5.
- **Security floor:** Google auth; RLS on `checks`, `corrections` and `consents`; server-side validation on every input; no secrets in the repo (Vercel env vars only); the report is re-computed on the server at save time, never taken from the browser.
- **Known fact checks:** SOLIDWORKS does not support Windows Home, Boot Camp or Windows 10 for 2026+; Premiere needs Windows 11 v24H2; Visual Studio ARM64 does not support Python or data-science workloads; MATLAB on Snapdragon runs in emulation. AutoCAD's GPU spec includes bandwidth that cannot be compared, so it stays `cannot_decide`.

## Session 2 (2026-10-18): deploy and test
- **Stack:** Vercel Hobby + a new Supabase project (`cotejo`) + Google OAuth client. Live at https://cotejo-tau.vercel.app/ . Repo: https://github.com/emiliogomezbuilds/cotejo .
- **Deploy 1 problems (infrastructure, not code):**
  1. Sign-in failed with "No API key found in request": `NEXT_PUBLIC_SUPABASE_URL` had `/rest/v1/` appended. The correct value is the bare project URL.
  2. Vercel would not save the edited variable: a `NEXT_PUBLIC_` value cannot be Secret. Deleted and recreated as Config, then redeployed. `NEXT_PUBLIC_` values are baked in at build time, so a redeploy is required after any change.
  3. The first git push was rejected because GitHub had created a starter commit; solved with a force push of the local history (packet first).
- **Live walkthrough on the deployed site:** sign-in, check, save, dashboard, delete, the text helper (Ryzen 5 / 16 GB / 512 GB / Windows 11 Home / 17,999 pesos: all five fields proposed and marked) and the screenshot helper on an invented listing. The verdicts after an AI-proposed form were identical to the manual ones, with the same quotes and links.
- **Mechanical pass, bug found on the live URL and fixed (deploy 2, 7e86670):** with the operating system left at "No lo sé" the result page was a dead end: a grey "Elige el sistema operativo…" line, a save form for a result that said nothing, and only a small "Cambiar datos" button. Fix: an amber box that names the missing field with an "Elegir el sistema operativo" button that returns to the form and focuses the field; the save form is hidden; the server also refuses to save a check with no OS. Same commit: grey placeholders (16, 512, 17499) now read "ej. 16" because they looked like pre-filled data.
- **Persona test (Valeria, 18, first-year design student, phone-only):** played by me on the live site and written up with the build assistant (see PERSONA). The worst confusion, also my own observation ("results page was long"): a result runs to dozens of cards with no summary, and a new user cannot tell what "sin resolver" means or whether red means she must not buy. Fix (deploy 3, 6f1d38c): the result opens with a per-program summary with links ("Resumen por programa", counts only, no overall grade) and a plain-language legend: "No cumple" is a vendor rule her data does not meet, "Sin resolver" means Cotejo cannot decide it from what she declared and is neither a failure nor an approval, "Por debajo de lo recomendado" is a suggestion, quotes are in English because the vendor publishes them in English, and Cotejo does not tell her to buy or not to buy.
- **Known limits (not fixed, written down):** the screenshot helper left or got some fields wrong on the invented listing; details are in PERSONA. Vendor quotes are in English. Verdicts are only as current as 2026-10-18; vendor pages change and the SOLIDWORKS page metadata is dated 2024. Only 5 titles, Windows and macOS only; no Linux, ChromeOS or used/refurbished knowledge. The page was tested on a desktop-width browser, not on a phone. No real student has used it, so the persona log is a floor. "No cumple" for Windows Home does not say whether an upgrade is possible; Cotejo does not claim it.

## Session Close
- **What exists:** live app with Google sign-in, five-title evidence catalog, three-state engine with a source on every line, optional text and screenshot helpers that only propose, confirm-before-check, per-program summary and legend, optional saved checks tied to a catalog version, error reports on any requirement, delete one check or all data, evidence and privacy pages. 514 offline checks pass (`npm run verify`).
- **What changed my mind:** I expected the hard part to be the engine: being strict about what it refuses to decide. It was not. The first time I used the live site with a field left empty, the engine did the correct thing, "cannot decide", and the page was still a dead end. A correct "I don't know" with no way forward is still a failure for the person. The honesty has to come with the next step.
- **What I would do next, in order:** (1) put it in front of three real first-year students on their phones and watch where they stop; (2) translate the vendor quotes without changing their meaning, or link a translation the vendor publishes; (3) re-read every vendor page on a schedule and show the age of each source; (4) ask whether a plain checklist would be enough, which is the dissent I carry into the team video.
- **What I would not do:** add any score, "good laptop" label, ranking, store link or commission.
